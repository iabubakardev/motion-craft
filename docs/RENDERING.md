# Phase 5 composition preview and local MP4 rendering

This is a verified desktop development pipeline, not a packaged Windows release. Source mode remains available; select **Timeline** above the monitor for the composition. **Export > Export MP4** opens native destination selection and reports actual worker progress. The current output is project-resolution H.264/yuv420p MP4 with AAC audio at the project sample rate and FPS. Odd resolution dimensions are rejected with an actionable H.264 error.

## Shared composition

`rendering/input.cjs` validates `{ project, sources }` with the existing strict project schema and a derived approved-URL map. This is not a second independently editable model and does not change schema v2. It resolves scene layers and standalone clips into frame placements. `project-composition.tsx` renders the same data in Player and in the headless composition registered by `entry.tsx`. Preview/export differ only in asset URL resolution and Remotion's decoding backend.

- Supported: video, still image, audio, text, caption-as-text and basic rectangle/ellipse layers; position, scale, rotation, opacity, text styling, image fit, track ordering, visibility/mute and layer volume/mute. Existing fade-in/slide-up entrance presets are evaluated from frame time. There is no CSS animation clock.
- Tracks are drawn from bottom to top (descending track order); within a track, layer zIndex then stable clip ID determines drawing order. Audio tracks mix simultaneously. Hidden tracks omit all their content. Muted audio tracks are omitted; muted video tracks keep their pictures with audio disabled.
- Project background is drawn over opaque black, including gaps. H.264 output has no alpha channel. Root font/layout defaults are explicit to avoid inheriting editor CSS in preview. System/serif/monospace fonts use the same installed-machine fonts in both runtimes.
- The schema has no shape width/height, so unscaled shapes default to one third of canvas dimensions and use the existing scale/position properties. Text is centered in its full-canvas layer before its existing transform. Styles and scene transition presets are not applied; the export dialog states this limitation.
- Known missing media appears as a visual placeholder or silent audio in preview. Decode errors have explicit feedback rather than uncaught media exceptions. Headless decode failures fail the job; they never silently produce a successful placeholder export.

## Timing

Project seconds remain canonical. Supported project rates are 24, 25, 30, 50 and 60 fps; fractional/rational/drop-frame rates are not part of the schema.

Frame intervals are half-open: `from = ceil(start * fps)`, `end = ceil((start + duration) * fps)`, and duration is `end - from`. This samples frames whose project timestamps lie inside the clip. Tiny legacy intervals containing no frame samples are omitted. Project duration is ceil(total seconds * fps), with one frame only as an internal empty-composition scaffold; the UI handles an empty project and export refuses it.

Source in-points use nearest project frames, including the fractional difference between the first sampled timeline frame and the saved start. Sequence length clips the source out-point. This deterministic quantization is shared by preview and export and never rewrites saved seconds. Audio/video source offsets use project FPS, not an assumption about source media FPS.

## Player synchronization

`CompositionMonitor` memoizes the validated input/model on project/assets. It subscribes directly to the existing per-workspace Zustand store. Timeline frame changes seek Player only when its current frame differs; Player frame events update that store without document/history/workspace state changes. This comparison prevents feedback loops. Seek listeners/subscriptions clean up on replacement/unmount. Normal project edits keep the Player identity; document replacement resets it deliberately.

Timeline is the default monitor; Source inspection is explicit and independent. Timeline interactions automatically restore the linked preview. Space toggles the active monitor outside text/editable controls; Player provides play/pause, fit sizing, volume, seeking and fullscreen. The existing timeline timecode remains the frame-accurate readout. Switching modes releases the inactive media resources.

The secure Electron media protocol accepts base approved asset URLs plus strictly numeric `#t=start[,end]` temporal fragments generated by Remotion. Endpoints must be ordered, finite and within 24 hours. Fragments never affect ID lookup, path resolution or authorization. Queries, credentials, unknown IDs, other fragments and traversal remain rejected. Regression tests cover the narrow exception. This is required because Electron forwards media fragments to the custom protocol handler.

## Export boundary and lifecycle

The preload surface adds only `render.start(project)`, `render.status()` and `render.cancel(jobId)`. There is no raw IPC, renderer-supplied output path, shell or filesystem API. Main checks owning window, main frame, origin and exact tuples. Status is scoped to the originating window. Opening an output dialog is serialized and revalidated after awaits/navigation.

Electron selects a native `.mp4` destination and explicitly confirms existing-file replacement. The main process rejects a destination matching declared source media. A render captures an immutable project and approved-binding snapshot; later editor edits do not change that job. The UI describes this snapshot behavior.

`render-jobs.cjs` launches `workers/render.cjs` as a dedicated Node child through Electron's Node runtime with fixed module/argument lists, hidden process windows and no shell commands. Node-only renderer/bundler imports are forbidden by ESLint in browser-facing modules. The persistent editor document/history is not duplicated in the job store.

States: idle (no job), preparing, bundling, rendering, finalizing, completed, failed, cancelling and cancelled. Jobs have UUIDs, validated progress and safe messages. Bundling/rendering percentages come from Remotion callbacks; preparing waits for actual browser/resource preparation. UI polling is bounded and cleaned up on unmount; hiding the dialog keeps the job running and reopening reads its status. Only one export may run at a time.

The worker probes actual playable source streams/ranges (rather than trusting imported duration metadata), creates a temporary bundle, prepares Chrome, uses the shared composition and renders with concurrency 2. It verifies codec, dimensions, FPS, video duration (within one frame) and required AAC audio using FFprobe. Output is written to a unique sibling partial file, synced, then atomically renamed after checking that the destination still matches the confirmed file fingerprint. The previous file remains intact on failure/cancel. A final rename already in progress cannot be reversed by a later cancellation.

Cancellation uses Remotion's cancel signal and a bounded process-tree termination fallback. Window navigation/destruction releases its job; normal application shutdown stops the worker tree. Worker disconnect also cancels and has a bounded exit fallback. Temporary bundles, media service connections and partial output are cleaned on normal completion/failure/cancellation. Abrupt OS termination can still leave temporary files; crash recovery is not implemented.

## Headless media access

Electron custom-protocol URLs are not assumed to work in headless Chrome. Each job creates a server bound to `127.0.0.1` on an ephemeral port with a random 256-bit capability token. Routes contain only that token and an approved asset UUID; there is no directory serving or URL-to-path translation. Host, Origin, method, ID and token are checked. Every request verifies canonical path and size/mtime/inode against the captured native binding. Changed files fail closed. GET/HEAD and validated byte ranges support Chromium and FFmpeg streaming, with explicit MIME/no-sniff and narrow loopback CORS.

Only this derived loopback URL map crosses into the headless browser. Native paths stay in Electron/the trusted worker. Web security, renderer Node isolation, sandboxing, navigation and permission policies remain enabled. No cloud service is used.

## Dependencies, binaries and setup

All four direct packages are pinned to **4.0.540**: `remotion` (composition primitives), `@remotion/player` (embedded playback), `@remotion/bundler` (job-local composition bundle) and `@remotion/renderer` (headless rendering/cancellation). They support the installed React 19 version and are checked against the installed APIs. OffthreadVideo uses HTML video for Player and FFmpeg frame extraction for export; Html5Audio and Img avoid another media decoder dependency. No additional form, query, queue or test runner is required.

Remotion uses its own license. Review its installed LICENSE.md and [upstream licensing terms](https://www.remotion.dev/license) before distributing MotionCraft. The development workflow has no cloud-rendering API requirement.

```bash
npm install
npm run render:setup
npm run dev
# Clear inherited ELECTRON_RUN_AS_NODE before native Electron commands:
npm run electron:dev
```

`render:setup` detects the pinned Remotion platform package's FFmpeg/FFprobe executables and prepares/caches Chrome Headless Shell. The initial browser download requires network access; rendering uses local resources afterward. The current binary adapter explicitly supports Windows x64, and does not depend on PATH. Packaged delivery must bundle the correct binaries, composition entry/bundle, Chrome/cache strategy, licenses and writable temporary locations; existing Electron production loading is still unconfigured.

## Verification

```bash
npm run check
npm run build
# Against the running Next dev server, with ELECTRON_RUN_AS_NODE cleared:
npm run test:desktop
npm run test:media
npm run test:projects
npm run test:timeline
npm run test:render
```

The full suite has 58 unit/security/lifecycle tests. Render tests cover conversion/frame bounds, visibility/order/transforms, audio offsets/mute, missing sources, unsafe render URLs, output metadata, scoped media HTTP/ranges/fingerprints, IPC tuples/sender revalidation, job progress, terminal states, cancellation, failures and destination races. Phase 4 fixtures now inject creation time so their fixed command timestamps remain valid across days.

`test:render` uses a real Electron Player and worker, native media registry and temporary generated H.264/PNG/WAV fixtures. It verifies a **decoded preview pixel**, playback-to-playhead updates and source-offset seeking. It creates and probes a real 320x180, 30 fps, 2-second H.264/AAC MP4, decodes a pixel to verify source trimming, measures audio silence boundaries for the expected 0.5-1.5 second interval, checks progress/conflicting export rejection and cancels a second render while asserting that the earlier MP4 remains byte-identical. Native dialogs are substituted. The output path is printed; fixtures/profile/output stay under ignored `.next/render-smoke-*`, and `.next/render-preview-smoke.png` captures the workspace. Next builds may clear these generated artifacts.

The deterministic, path-free `public/render-sample.motioncraft.json` provides a two-second graphics/text project. `rendering/sample.cjs` is its shared test fixture factory. Preview and export use the exact same composition component.
