## Existing gaps found and changes made

The previous AI Production dialog already supported local planning and reviewed append assembly. It did not automatically consume the selected audio clip, reuse canonical reviewed transcripts, style all generated captions with a chosen preset, or refuse short/unresolved visuals before assembly. Whole transcription segments could also be repeated in adjacent scene narration when a boundary split the segment.

The new **AI Create Video** toolbar action adds a focused orchestration dialog in `features/ai/ai-create-video.tsx`. It reuses the secure AI job hook, native audio inspection/settings, canonical transcript/project contracts, existing Ollama provider, existing apply-plan/caption operations, project snapshot history and existing preview/export pipeline. No new dependency, IPC capability, external API, database or Python protocol was added. Legacy AI Production remains available.

`core/ai/create-video.cjs` owns source-relative to clip-relative transcript mapping, covering-range/fingerprint reuse, lexical media matching and immutable assembly. `core/ai/planning.cjs` now assigns each word (or unaligned segment) to one scene by canonical start, so boundaries cannot duplicate whole segments. The model never controls source timing: the application deterministically partitions the narration into contiguous positive scenes before asking for descriptions. Zod rejects overlapping/gapped plans, invented IDs and extra fields; invalid JSON/descriptions retry once and then fail visibly. There is no silent fabricated-plan fallback.

Scenes expose app ID, narration start/end, canonical narration, editable visual description, keywords, image/video requirement, animation and cut/fade-in suggestion. No media catalog IDs or native paths are supplied to Qwen. The app chooses asset IDs after inference.

Matching uses filenames and descriptions/tags from the existing trusted asset index, plus optional descriptions entered in this dialog. Scores are labeled **lexical confidence**, not visual-semantic confidence or probabilities. A positive keyword match and full scene coverage are necessary for automatic selection. Unmatched scenes remain explicit unresolved placeholders in review. Users can make a manual choice and explicitly approve it; no relevance claim is made for unrelated manual choices. Videos shorter than their scenes cannot be selected or assembled. Dialog-only description edits affect this review and are not written back to the index; persistent index editing remains in Smart asset search.

Assembly replaces the timeline only after explicit replacement confirmation when it contains content. It preserves the library, source files and original transcript archive, resets generated track audibility, maps source trim/rate correctly, creates full-duration visuals and narration plus styled caption clips, then commits once. Undo restores the complete previous document, including its canvas, tracks, clips, animation and transcripts. Locked populated tracks block replacement. Project changes while inference/inspection is pending reject stale assembly. The result is ordinary editable timeline data.

Both 16:9 (1920x1080) and 9:16 (1080x1920) are available. Portrait assembly is domain-tested; this POC's actual encoded acceptance is landscape. Target scene seconds are a grouping preference, not permission for Qwen to change narration duration. Wordless/manual transcripts retain segment text without fabricated alignment. Ambiguous partial segments need range transcription first; zero-duration Whisper words retain segment text with no fabricated word timing.

## How to use

1. Import narration audio and suitable images/footage. Select one audio timeline clip, or select its imported audio asset.
2. Click **AI Create Video**. A single selected narration is already populated; its trim and playback rate are respected. Otherwise choose an imported audio asset once.
3. Select aspect ratio, caption preset, scene target and optional style instructions. Add descriptions where filenames are not useful. Click **Generate video plan**.
4. A valid saved covering transcript is reused. Otherwise the existing local Whisper worker runs, followed by local `qwen3:8b`. Errors/cancellation stay visible; no paid fallback is used.
5. Review descriptions, lexical evidence and each asset. Resolve every placeholder, approve the matches and confirm replacement if needed. Click **Assemble video**.
6. Preview in the Timeline monitor, adjust ordinary clips/captions and use the existing **Export** action for local MP4 output. Save the project to persist the reviewed transcript and edit state.

Requires the desktop bridge, configured/default Python worker with cached Whisper model, a running local Ollama with `qwen3:8b`, imported narration and full-length scene visuals. Missing visuals, models, offline media, track locks or changed project/source state produce errors rather than a false success.

## Verification and first MP4 outcome

- `npm run check`: lint, strict TypeScript and domain/security/worker regressions, including `core/ai/create-video.test.cjs` (timing, canonical text, strict model validation, matching, missing/short media, caption alignment/styles, source-rate mapping, history and persistence). Existing worker tests cover bounded repair/retry and malformed model output.
- `npm run build`: production compilation/type checking.
- `npm run test:ai:create-video`: **actual** isolated Electron run using local tiny faster-whisper and `qwen3:8b`. Checks one selected 1-9 second narration range without repeat source selection, real structured planning, manual match approval, replacement confirmation, generated caption styling, atomic undo/redo, native save/reload and transcript reuse. Renders a real 8-second 1920x1080/30fps H.264/AAC MP4, probes metadata, decodes first/middle/end visuals and compares source-range/encoded audio levels. Saves plan JSON, project JSON, verification JSON, workspace screenshot and decoded frames under ignored `.next/ai-create-video-*`.
- The visual fixture is an explicitly approved generated blue test card; it is deliberately not represented as automotive footage matching the speech. This proves pipeline integration, timing and readability, not meaningful editorial media matching quality. No representative user media was modified and no online assets were fetched.
- Initial verification hit two test assumptions: pinned FFmpeg supports PCM WAV rather than raw `s16le` output, and Electron bitmap pixels use BGRA channel order. The output was inspected visually, the checks corrected, and the complete smoke rerun passed.

Final verification: `npm run check` passed all 158 tests with strict TypeScript and zero lint errors (one existing unused-variable warning in `workers/asset-index.cjs`). Production build and native `test:ai:create-video`, `test:ai:planning`, `test:captions` and `test:visual` passed. The final POC artifacts are in `.next/ai-create-video-cGAH1g/`: `ai-video-1080p.mp4`, `ai-video.motioncraft.json`, `scene-plan.json`, `verification.json`, `workspace.png` and three decoded frame PNGs. Audio speech-envelope correlation is 0.9924 with a measured -10 ms offset; output is 1920x1080, 30 fps, 8 seconds, H.264/AAC. Generated files are ignored and may be removed by a future Next build. Physical listening and representative footage review were not performed.

## Remaining blockers and recommended next improvements

1. Import a representative relevant footage/image library and review narration/asset quality manually; lexical matching cannot recognize a visual subject without useful filenames, tags or descriptions. The workflow is human reviewed, not autonomous semantic editing.
2. Implement true cross-scene dissolves separately. Current fade-in entrances may reveal the intentional project background during the fade and motion presets take priority; they are not a claim of seamless overlapping transitions.
3. Run a portrait native export, broader codecs and longer narration with memory/interaction profiling. Current acceptance is an eight-second landscape fixture and CPU inference.
4. Physical playback/listening, native picker interaction and packaged/offline renderer/model provisioning remain release gates. Existing dependency/security and Remotion distribution-license findings remain in ENGINEERING_AUDIT.md.
5. Add durable plan drafts and explicit per-scene replacement/regeneration without requiring whole-video replacement. Current drafts live in the dialog, result clips are editable, and source transcripts persist on assembly/save. Autosave/crash recovery is still missing.
